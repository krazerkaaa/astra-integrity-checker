# Автоматизация проверки целостности критически важных файлов ОС Astra Linux

Инструмент предназначен для автоматизированного выявления несанкционированных модификаций, повреждений, удаления или изменения прав доступа критически важных системных файлов, конфигураций подсистемы безопасности PARSEC и загрузочных секторов в ОС **Astra Linux Special Edition** (уровень защищённости «Смоленск»).

---

## 1. Архитектура и состав проекта

Программный комплекс реализован на языке Python 3 с использованием исключительно стандартной библиотеки (не требует установки сторонних пакетов в замкнутой программной среде) и состоит из четырёх модулей:

* `main.py` — единая консольная точка входа (CLI), объединяющая все режимы работы утилиты.
* `task1_scanner.py` — модуль инвентаризации критически важных объектов ОС (конфигурации `/etc`, модули ядра PARSEC, раздел `/boot/efi`, главная загрузочная запись `MBR`, сектора `1–63` и загрузочные сектора разделов `PBR`), а также менеджер ручного добавления и удаления путей (`add` / `remove`).
* `task2_hasher.py` — модуль потокового расчёта криптографических контрольных сумм **SHA-256**, сбора метаданных (`st_size`, `st_mode`, `st_mtime`), атомарного сохранения эталонной базы и сжатого резервного кэширования текстовых конфигураций.
* `task3_auditor.py` — модуль аудита целостности, который сверяет текущее состояние объектов с эталоном, выявляет изменения содержимого и прав доступа, выполняет построчное сравнение (`difflib`) с эталонной копией и формирует детализированный JSON-отчёт.

## 2. Системные требования и развертывание

* **Операционная система:** Astra Linux Special Edition 1.7 (уровень защищённости «Базовый», «Усиленный» или «Максимальный / Смоленск»).
* **Интерпретатор:** Python версии `3.7` и выше.
* **Права доступа и мандатный контекст:** Для чтения защищённых конфигураций (`/etc/shadow`, `/etc/pam.d/*`, каталогов PARSEC) и прямого доступа к блочным устройствам (`/dev/sda`, `/dev/vda`, `/dev/nvme0n1`) утилиту необходимо запускать от имени суперпользователя (`sudo`) в сессии с высоким мандатным уровнем целостности.

### Установка на целевой узел

1. Склонируйте репозиторий в системную директорию (например, `/opt/astra-integrity-checker`):
   ```bash
   sudo git clone https://github.com/krazerkaaa/astra-integrity-checker.git /opt/astra-integrity-checker
   cd /opt/astra-integrity-checker
   ```
2. Установите права доступа, запрещающие чтение и изменение скриптов непривилегированным пользователям:
   ```bash
   sudo chown -R root:root /opt/astra-integrity-checker
   sudo chmod 700 /opt/astra-integrity-checker
   ```

## 3. Руководство по использованию и примеры запуска

Все операции выполняются через управляющий скрипт `main.py`. Для просмотра встроенной справки используйте флаг `-h` или `--help`:
```bash
python3 main.py --help
```

### 3.1. Первичная инициализация и создание эталона (`build-baseline`)
Выполняется сразу после установки и базовой настройки защищённой ОС. Скрипт сканирует критические директории и загрузочные сектора, сохраняет список объектов в `critical_files_list.txt`, формирует эталонную базу `hashes_baseline.json` и создаёт сжатые резервные копии текстовых файлов в `.baseline_cache/`:
```bash
sudo python3 main.py build-baseline
```
Дополнительные параметры:
* `--list <путь>` — указать нестандартный путь для списка файлов (по умолчанию `critical_files_list.txt`).
* `--output <путь>` — указать путь для сохранения базы эталонов (по умолчанию `hashes_baseline.json`).

### 3.2. Проверка целостности и поиск изменений (`audit`)
Выполняет сверку всех объектов из эталонной базы с их текущим состоянием на диске:
```bash
sudo python3 main.py audit
```
**Что происходит при обнаружении нарушений:**
* В консоль выводится статус объекта (`[ИЗМЕНЁН]`, `[ОТСУТСТВУЕТ]`, `[НЕТ ДОСТУПА]`).
* Если изменились метаданные, утилита показывает разницу в размере (в байтах), смену прав доступа (`chmod`) и время модификации.
* Если изменён текстовый конфигурационный файл, встроенный анализатор `difflib` выводит **конкретные номера и содержимое удалённых, добавленных или переписанных строк**.
* Подробный структурированный отчёт сохраняется в `integrity_report.json`.

Пример запуска с указанием собственных путей к базе и отчёту:
```bash
sudo python3 main.py audit --baseline /opt/astra-integrity-checker/hashes_baseline.json --report /var/log/audit_report.json
```

### 3.3. Добавление нового файла под контроль (`add`)
Позволяет включить любой дополнительный файл в контур мониторинга. Утилита проверит доступность файла, добавит его в `critical_files_list.txt`, вычислит SHA-256 и сразу запишет эталон и резервную копию в кэш:
```bash
sudo python3 main.py add /etc/sudoers
```

### 3.4. Удаление файла из списка контроля (`remove`)
Исключает файл из списка отслеживания `critical_files_list.txt`, удаляет запись о нём из `hashes_baseline.json` и очищает его резервную копию из `.baseline_cache/`:
```bash
sudo python3 main.py remove /etc/sudoers
```

### 3.5. Обновление эталона после легитимных изменений (`update`)
Применяется администратором после планового обновления пакетов или санкционированной правки настроек:
* Точечное обновление одного файла (без пересканирования всей системы):
  ```bash
  sudo python3 main.py update /etc/ssh/sshd_config
  ```
* Полный пересчёт всей эталонной базы по текущему списку контроля:
  ```bash
  sudo python3 main.py update
  ```

### 3.6. Полный цикл проверки (`full-check`)
Последовательно выполняет сканирование, пересборку эталона и контрольный аудит за один вызов:
```bash
sudo python3 main.py full-check
```

## 4. Статусы объектов и коды возврата

### Статусы объектов в отчёте (`integrity_report.json`)
| Статус | Описание |
| :--- | :--- |
| `OK` | Контрольная сумма SHA-256 и метаданные полностью совпадают с эталоном. |
| `CHANGED` | Обнаружено изменение содержимого файла, загрузочного сектора или метаданных (`st_size`, `st_mode`, `st_mtime`). |
| `MISSING` | Файл или блочное устройство не найдены по указанному пути (удалены или перемещены). |
| `UNREADABLE` | Недостаточно дискреционных или мандатных прав для чтения объекта. |
| `ERROR` | Системная ошибка ввода-вывода при обращении к файлу. |

### Системные коды возврата (`Exit Codes`)
Утилита возвращает стандартные коды завершения для интеграции с системами мониторинга и планировщиками задач:
* `0` — проверка завершена успешно, отклонений не выявлено.
* `1` — обнаружены нарушения целостности (`CHANGED`, `MISSING`, `UNREADABLE`) или ошибки при работе со списком файлов.
* `2` — критическая системная ошибка (отсутствует файл эталона, повреждён JSON, неверные аргументы запуска).

## 5. Настройка автоматического аудита по расписанию (`cron`)

Для регулярного фонового контроля целостности без участия оператора добавьте задание в системный планировщик `/etc/crontab` (пример для ежедневной проверки в `03:15` от имени `root` с записью журнала):

```cron
15 3 * * * root /usr/bin/python3 /opt/astra-integrity-checker/main.py audit --baseline /opt/astra-integrity-checker/hashes_baseline.json --report /var/log/integrity_report.json >> /var/log/integrity_checker.log 2>&1
```

## 6. Рекомендации по безопасности эксплуатации

1. **Защита эталонной базы и кэша:** Файл `hashes_baseline.json` и директория `.baseline_cache/` создаются утилитой с правами `0600` и `0700` соответственно. Не ослабляйте эти права, так как в кэше хранятся резервные копии системных конфигураций.
2. **Хранение эталона на доверенном носителе:** Для защиты от подмены самой эталонной базы злоумышленником, получившим права `root`, рекомендуется дублировать `hashes_baseline.json` на внешний носитель (доступный только для чтения) или удалённый сервер сбора логов.
3. **Анализ срабатываний:** Статус `CHANGED` фиксирует сам факт модификации. При его появлении необходимо сверить время изменения (`st_mtime`) с журналом установки обновлений (`/var/log/apt/history.log`) и журналом аудита безопасности Astra Linux.
